01 · Architectural Foundation

Executive Overview: The 6×6 Orthogonal Matrix & 22-Table tview_* Schema

Every element created in a .tvwx repository (or synced across PostgreSQL, MySQL, and Redis) is stored in a normalized 22-table tview_* relational schema and projected into a 36-cell (6 Perspectives × 6 Interrogatives) property graph evaluated by the native Rust CSR Graph Engine (tview-graph-core).

04 · Formal Semantic Integrity & Graph Algorithms

How the Rust CSR Graph Core (tview-graph-core) Validates Metamodel Lineage

Implemented in rust/tview-graph-core/src/lib.rs and orchestrated by internal/earepo/reasoning_engine.go, TreeviewEA compiles all repository objects and connectors into a dual-indexed Compressed Sparse Row (CSR + Reversed CSC) property graph and enforces 4 mathematical invariants:

INVARIANT 1 · I_TRACE_VERTICAL

5-Stratum Lineage Reachability

Executes a bidirectional 5-hop BFS across HasScopeToConceptLink (R1→R2), HasConceptToLogicLink (R2→R3), HasLogicToPhysicsLink (R3→R4), HasPhysicsToAssemblyLink (R4→R5), and HasAssemblyToOpsLink (R5→R6). Flags unbacked microservices or tables as SHADOW_INFRASTRUCTURE_DRIFT.

INVARIANT 2 · I_TYPED_MORPHISM

Layer-Bypass Erosion Detection

Evaluates |stratum(u) - stratum(v)| for every directed edge. Any connector that skips ≥ 3 abstraction strata (e.g., wiring an L0/L1 Business Capability directly to an L4 AWS RDS instance without an intermediate L2/L3 Component/Table) emits a LAYER_BYPASS violation.

INVARIANT 3 · I_DAG_CONTAINMENT

Tarjan SCC Cycle Detection

Runs Tarjan's Strongly Connected Components (detect_cycles_tarjan) in O(|V| + |E|) time over CSR row_ptr / col_idx arrays to isolate circular microservice or package dependencies (CYCLIC_DEPENDENCY_CREEP).

INVARIANT 4 · I_CANONICAL_SCHEMA

PayEx / Transaction Hub Lineage & Centrality

Verifies ISO 20022 dot-notation attribute coverage ($.onBehalfOfPayer, $.returnSpecificInfo, $.enrichedDataInExchange, $.exchangeRate) and computes Power-Iteration PageRank, Brandes Betweenness Centrality, and 3-Hop Blast Radius.

06 · Multi-Model Governance & Roadmapping

Building Execution, WBS & FinOps Plans for 1...M Models

Whether you are governing 1 Enterprise Capability Model fanned out into M Domain Microservice Models or sequencing Baseline ("As-Is") → Wave 1..N Transition Models → Target ("To-Be") Architecture, TreeviewEA provides three structural patterns backed by live WBS, Gartner TIME, and FinOps rollups.

PATTERN A · MULTI-PREFIX / MULTI-FILE

1 Database → M Isolated Table-Prefix Schemas

Use manage_project_lifecycle with storageMode='schema' and custom prefixes (e.g., tview_ for Baseline, wave1_ for Transition Wave 1, target_ for To-Be) inside a single .tvwx or PostgreSQL database, or clone separate .tvwx files in < 50ms.

PATTERN B · MULTI-PACKAGE HIERARCHY

1 Root Repository → M Domain / Wave Packages

Organize 1...M models as packages in tview_packages. Use manage_packages(action='duplicate') to branch a baseline package subtree into a new Transition Wave package, and wire cross-package traceability connectors in tview_connectors.

PATTERN C · CANONICAL OBJECT PROJECTION

1 Canonical Object → M Visual Diagrams

Store each capability, microservice, class, or table once in tview_objects (Object_ID) and project it onto 1...M diagrams in tview_diagram_objects via manage_diagrams(action='place_objects'). Updating an attribute or status updates all M diagrams automatically.
